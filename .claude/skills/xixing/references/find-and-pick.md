# Phase 0 · 去哪找，怎么挑

> 最容易被跳过、也最决定后面质量的一步。挑错对象，后面四步都是白干。

## 去哪找（GitHub 类）

| 入口 | 说明 |
|---|---|
| `github.com/topics/claude-skills` | 按话题翻，能看到最新的 |
| `github.com/topics/agent-skills` | 同上，覆盖面更广 |
| GitHub 搜索框 | `topic:claude-skills amazon`、`topic:agent-skills ecommerce` |
| `hikari0511/awesome-amazon-ec-skills` | 中文合集，Amazon 出海 + 1688 上游 |
| `nexscope-ai/Amazon-Skills` | 52 个 Amazon skill，原型案例用的就是它 |

**GitHub 搜索的语法坑**：自然语言长串（`turn any url into diagram`）返回 0 条。
用 `topic:` ／ `in:name,description` ／ `stars:>100` 这类限定词，一次一个角度多跑几条。

**直接丢给 AI 也行**：
```plaintext
上 GitHub 找和「[你那一环]」相关的开源 agent skill 或工作流仓库。
按 star 数排前 10 个，每个告诉我：star 数、最近更新时间、它解决哪一步、目录里有多少个 skill。
不要只看名字，打开 README 确认它真的做这件事。找不到就说找不到，不要编。
```

## 怎么挑（四判据，缺一个就换一个）

```
① star > 100        有人真用过、验证过，不是个人练手
② 三个月内有更新     没死。AI 生态半年一代，两年没更新的参考价值有限
③ 目录能对上你的环节  打开仓库先看文件夹名，对不上就别硬吸
④ 单份 200–600 行    太短没结构不值得画图，太长一次吃不完
```

> 📌 实测：`amazon-listing-optimization` 是 **428 行**，正好在区间里，萃取约 12 分钟。
> 1000 行以上的建议先拆成两次。

## 非 GitHub 输入怎么挑

| 输入 | 判据 |
|---|---|
| **视频** | 有没有**结构**（讲流程/讲方法论）。纯观点、纯资讯、纯情绪的视频吸不出流程图，别浪费转写时间 |
| **文章** | 同上。带步骤/带判断条件的才值得。"十大趋势"这类列表体没有执行路径 |
| **PDF / 书** | 先看目录定位到讲方法的那几章，别整本吸 |
| **公司/品牌** | ⚠️ 不归本 skill —— 那是「调研一个组织」，该走专门的公司/品牌调研流程 |

## 一条通用的判断

**看它有没有「什么时候该回头/该换路」的描述。**
只写"第一步第二步第三步"的材料，萃取出来是一条直线，没有判断，学不到东西；
真正有价值的材料里一定有分支和回退——那些才是作者踩过坑的地方。
